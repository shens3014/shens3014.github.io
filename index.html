Agent 编排与执行控制

设计多步任务时，我先区分哪些信息可以并行获取，哪些结论必须等待上一步。以财务比较为例，两家公司的报表可以同时查；计算增长率之前，要先对齐报告期、币种和单位。

金融检索与证据排序

金融查询常混合两类需求：证券代码、报告期需要精确匹配，同义表述和跨段落描述适合语义检索。我结合两种召回方式，用相关段落在前几位的命中情况及检索延迟，判断是否值得增加重排。

历史研究还需要定义信息截止时间。年报写的是上一年的经营情况，市场能够读到它的时间却是披露日。我按披露日限定候选材料，避免后来发布的年报进入历史回答。

Agent 评测与错误归因

我把评测拆成三个问题：工具有没有取到目标数据，模型有没有正确理解数据，输出里的结论能不能找到依据。即使引用了正确的报表，也可能把单季利润读成累计利润。

诊断时用同一道题逐层核对检索段落、工具结果和最终回答。原文缺失就检查检索；原文正确而数字错误，就追查抽取、单位换算和计算步骤。用固定题集回归，观察正确性、耗时和调用成本如何一起变化。

工具调用评测 · 检索评测 · 引用核验

全栈开发与状态一致性

做流式 AI 界面时，我把提交问题、工具执行和回答结束区分为不同状态。用户看到的每条工具结果都要能对应到发起它的调用，两个并行请求即使以相反顺序返回，也应更新各自的状态。

服务端负责会话和事件顺序，前端负责呈现及恢复。联调时分别检查短暂断网、页面刷新和会话失效：前两种情况需要续传或重建视图，会话失效则需要明确结束等待。

A 股数据与选股归因

我先明确筛选日的股票范围、财务数据可用时间和流动性条件，再比较量价、基本面与板块指标。分析个股落选时，先区分它是否满足入池条件，再看哪些指标拉低了排名。

总分相同的两家公司可能分别受益于低估值和高增长。保留分项和数据日期，才有机会判断某次排名变化来自基本面更新、价格波动，还是候选股票范围发生了变化。

Python · pandas · 量价指标 · 多因子筛选

成交模拟与回撤分析

回测先对齐信号、下单与可成交时刻。若选股依据包含当天完整成交量，就要等收盘后确认信号，再用后续可交易价格模拟执行，并考虑涨停限制、可卖数量、手续费和滑点。

解释回撤时，我同时看胜率、平均盈利与平均亏损，再回到回撤区间内的交易记录。少数大额亏损和连续小额亏损可能产生相似的净值曲线，却分别指向仓位暴露、入场条件或退出规则等不同问题。
